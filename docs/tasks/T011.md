## Objective
Implement the Android Scenario Configuration screen (`E3`), Experiment Comparison screen (`E4`), and Favourites / Cached Data / Offline Demonstration & Sync Settings screen (`E6`), replacing their placeholders in `MobilisNavGraph` (`REQ-009`, `REQ-010`, `REQ-011`, `BR-005`–`BR-008`, `BR-015`, `CON-009`, `DEC-002`).

## Contracts
- **E3 (`ui/scenarios/ScenariosScreen.kt`, `ScenariosViewModel.kt`)**:
  - Local Room-persisted scenario CRUD: `+ New`, `Save`, `Edit`, `Delete` (with mandatory confirmation `AlertDialog` per `BR-008`), `Run`, and `View results`.
  - Form inputs validated via `ScenarioValidator` (`T008`, `BR-007`, `DEC-002`):
    - Scenario name (required), Route selector, Trip/Journey selector, Intervention Stop selector, Additional stop-hold delay (`0–900 s` integer), Optional background traffic multiplier (`0.5–2.5`, defaulting to `1.0`), Demand profile, Departure time, Simulation seed.
  - Displays paired-experiment invariants checklist (`Same network & demand`, `Same departure & seed`, `Separate paired experiment` — `BR-005`).
  - Submission behavior:
    - Disabled with explicit connectivity notice when offline or in `DEMONSTRATION` mode (`BR-015`).
    - Disables `Run` button while job submission/execution is active for that scenario so rapid double-taps cannot create duplicate jobs (`BR-008`).
    - Tracks job states (`Queued`, `Running`, `Completed`, `Failed`); on failure, preserves all form fields and shows error message + `Retry` (`BR-008`).
- **E4 (`ui/scenarios/ComparisonScreen.kt`, `ComparisonViewModel.kt`)**:
  - Reads saved `ScenarioResultEntity` (or refreshes from `GET /experiments/{jobId}` when online).
  - Displays `Baseline: EXP-xxx` and `Scenario: EXP-yyy`, shared invariants summary (`network`, `demand`, `departure`, `seed` — `BR-005`), intervention details (`stop hold` and/or `traffic multiplier`), explicit label *"Observed Arrivals in the Simulation"* (`BR-006`, distinct from predicted delay), and stop-by-stop table (`Stop`, `Baseline`, `Scenario`, `Observed Difference`).
  - Actions: `View on route` (opens E1 with scenario context) and `Back to scenario` (returns to E3) (`REQ-009`).
- **E6 (`ui/favourites/FavouritesScreen.kt`, `FavouritesViewModel.kt`)**:
  - **Saved Stops section (`REQ-010`)**: displays persisted favourites in `displayOrder`, with accessible `Open` (navigates to E2), `Move Up`, `Move Down`, and `Remove` controls; accessible offline.
  - **Offline / Cached Data banner**: renders `OfflineStaleBanner` with last reception time and `Try again` whenever offline/stale (`REQ-011`).
  - **Built-in Offline Demonstration player (`REQ-011`, `BR-003`, `BR-004`, `BR-015`)**: `Open recorded trip`, `Play`, `Pause`, `Restart`, displaying current playback clock (`HH:MM:SS`), `DEMONSTRATION` badge, and notice *"New simulations require a connection"*.
  - **Connection & Sync Settings card (`DEC-003`, `CON-006`)**: editable Server Base URL (with Save + Test Connection), Sync Mode toggle (`Standard Polling` vs. `Live Demo Stream (SSE < 2 s)`), and Polling Interval selector (`1 s`, `5 s` default, `30 s`) for `EVAL-004` measurements.

## Implementation steps
1. Implement `ScenariosViewModel` and `ScenariosScreen` (E3) with full Room CRUD, client validation, delete confirmation dialog, duplicate-submit guard, failure input preservation, and status polling.
2. Implement `ComparisonViewModel` and `ComparisonScreen` (E4) rendering paired IDs, invariants, observed stop-by-stop arrival differences, and navigation actions.
3. Implement `FavouritesViewModel` and `FavouritesScreen` (E6) with reorderable favourites, offline stale banner, bundled demonstration Play/Pause/Restart controls, and server/sync settings.
