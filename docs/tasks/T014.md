## Objective
Implement the tool-restricted LangGraph conversational scenario analysis assistant backed by local Ollama (with OpenAI-compatible external API fallback via environment variables), strictly limited to the three typed backend tools (`list_scenarios`, `run_delay_experiment`, `compare_experiments`) with server-side validation, clarification prompts on ambiguous/out-of-range inputs, verbatim DB-grounded comparison tables citing stored experiment IDs, and integrate the chat UI into `/admin` (`REQ-015`, `BR-002`, `BR-006`, `BR-007`, `BR-013`, `CON-007`, `DEC-002`).

> **Review Flag**: Security-sensitive & correctness-critical task (strict 3-tool allowlist, pre-execution argument validation against prompt injection / out-of-range runs, grounded numeric output without LLM hallucination).

## Contracts
- **`backend/app/agent/llm_factory.py` (`CON-007`)**:
  - `create_chat_model(settings: Settings) -> BaseChatModel`:
    - When `settings.llm_provider == "ollama"`: returns `ChatOllama(model=settings.llm_model, base_url=settings.ollama_base_url, temperature=0)` (default `qwen2.5:3b` fitting 4 GB VRAM).
    - When `settings.llm_provider == "openai_compatible"`: returns `ChatOpenAI(model=settings.llm_model, base_url=settings.openai_api_base, api_key=settings.openai_api_key, temperature=0)` (hardware contingency without changing graph code!).
    - Accepts an injected `chat_model` override in tests so `pytest` runs deterministically without requiring live Ollama.
- **`backend/app/agent/tools.py` (STRICT 3-TOOL ALLOWLIST, `BR-013`, `DEC-002`)**:
  1. `list_scenarios(route_id: str | None = None, demand_profile: str | None = None, min_hold_s: int | None = None, max_hold_s: int | None = None, status: str | None = None)` → queries central backend experiment repository/service (`REQ-014`/`REQ-015` parity).
  2. `run_delay_experiment(name: str, route_id: str, intervention_stop_id: str | None = None, stop_hold_s: int = 0, traffic_multiplier: float = 1.0, demand_profile: str = "campus_rush", departure_time_s: int = 50400, random_seed: int = 42)` → validates via `ExperimentCreateRequest` + DB stop check, launches paired run via `ExperimentJobManager` (waiting up to configurable timeout or returning job status + `EXP-xxx` IDs and observed comparison when completed).
  3. `compare_experiments(baseline_experiment_id: str, perturbed_experiment_id: str)` → validates both IDs exist and are completed, returns exact stop-by-stop observed arrival comparison from DB (`BR-006`) or structured `NOT_FOUND` payload (`BR-013`).
- **`backend/app/agent/graph.py` (LangGraph `StateGraph`)**:
  - `AgentState(TypedDict)`: `messages`, `pending_tool_calls`, `validation_errors`, `executed_tools`, `cited_experiment_ids`, `structured_table`, `needs_clarification`, `step_count`.
  - Nodes & deterministic guardrails:
    1. `reason_or_clarify`: calls `llm.bind_tools([list_scenarios, run_delay_experiment, compare_experiments])` with a concise system prompt explaining Line 9 stops, bounds (`stop_hold_s ∈ [0, 900]`, `traffic_multiplier ∈ [0.5, 2.5]`), and strict prohibition against guessing missing parameters or inventing arrival numbers (`BR-002`, `BR-013`).
    2. `validate_tool_calls`: deterministic Python validation BEFORE executing ANY tool!
       - Verifies tool name ∈ `{"list_scenarios", "run_delay_experiment", "compare_experiments"}`.
       - For `run_delay_experiment`: verifies stop exists in DB (`route_id`), `stop_hold_s` is an integer in `[0, 900]`, `traffic_multiplier` in `[0.5, 2.5]`, and at least one intervention is non-zero (`BR-007`).
       - For `compare_experiments`: verifies both experiment IDs are provided and non-empty.
       - If any validation fails or parameters are ambiguous/missing → routes to `clarify_response` setting `needs_clarification = True` with zero backend tool executions!
    3. `execute_tools`: runs validated tools against backend services, appends exact tool output to `executed_tools`, extracts `cited_experiment_ids` (`EXP-xxx`), and populates `structured_table` (`{ title, columns, rows, data_origin: "OBSERVED_SIMULATED_DB" }`) verbatim from tool results (`BR-013`).
    4. `format_response`: asks LLM to summarize ONLY the returned `executed_tools` (or returns deterministic clarification message if `needs_clarification`), bounded by `max_steps = 6`.
- **REST Endpoint (`backend/app/api/agent.py`)**:
  - `POST /agent/chat`: body `{ session_id: str, message: str }` → returns `{ session_id, reply_markdown, needs_clarification, tool_calls: list[ToolCallAuditDto], cited_experiment_ids: list[str], structured_table: StructuredTableDto | null }`.
  - Keeps bounded in-memory per-session message history (capped at last 20 messages) and handles Ollama connection failures gracefully with HTTP `503` `ErrorEnvelope` (`LLM_UNAVAILABLE`) so the rest of `/admin` stays fully usable!
- **Admin Web Chat UI (`backend/app/web/`)**:
  - Activates `#agent-chat-panel` in `/admin`: message input, prompt suggestions (e.g., *"Hold bus 180 s at P02 and compare with baseline"*), chat transcript rendering `reply_markdown` safely (escaped text, zero raw `innerHTML` XSS), tool-audit pills showing which of the 3 tools ran, clickable `EXP-xxx` badges, and verbatim HTML table rendered directly from `structured_table` (`BR-013`).

## Implementation steps

6. Write `backend/tests/test_agent.py` with a deterministic fake tool-calling chat model testing ALL 5 `EVAL-003` task categories + unauthorized tool rejection + Ollama-offline 503 handling.

## Edge cases and security
- **Prompt injection / unauthorized tool defense**: Even if an LLM emits an arbitrary tool name or out-of-range arguments (e.g., `stop_hold_s=5000`, `stop_id="INVALID"`, or `drop_table`), `validate_tool_calls` MUST reject it before execution and return a safe clarification response with `executed_tools == []` (`BR-007`, `BR-013`).
- Never log or expose `settings.openai_api_key` in responses, logs, or `/health`.
- Render `reply_markdown` and `structured_table` in `admin.js` using safe DOM node creation (`textContent`), never `innerHTML`.
