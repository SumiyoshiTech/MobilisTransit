- **State**: `todo`

## Objective
Implement the Android network layer (Retrofit + OkHttp + `okhttp-sse` streaming), clock-offset synchronization and wall-clock latency telemetry logger, bundled offline demonstration player, and the unified single-source-of-truth `TransitRepository` consumed identically by 2D and AR views (`REQ-011`, `REQ-016`, `BR-003`, `BR-004`, `BR-009`, `BR-010`, `BR-015`, `CON-006`, `DEC-003`).

> **Review Flag**: Complex / concurrency-sensitive task (lifecycle-aware polling vs. SSE streaming, Room cache consistency, sequence ordering guard, clock-offset latency telemetry).

## Contracts
- **`data/remote/`**:
  - `MobilisApiService` (Retrofit + `kotlinx.serialization`): `getHealth()`, `getTime()`, `getRoutes()`, `getRouteStops(routeId)`, `getJourneys(routeId)`, `getJourneySnapshot(journeyId)`, `controlPlayback(journeyId, body)`, `createExperiment(request)`, `listExperiments()`, `getExperiment(id)`, `compareExperiments(baselineId, perturbedId)`, `postTelemetryEvents(events)`.
  - `SnapshotSseClient`: wraps OkHttp `EventSources.createFactory(okHttpClient)` subscribing to `GET /journeys/{id}/stream`, emitting `Flow<SseSnapshotEvent>` with automatic exponential backoff and fallback signal to fast `1 s` polling if SSE fails (`DEC-003`).
  - Dynamic base URL configuration (`ServerConfigStore` via SharedPreferences / DataStore, default `http://10.0.2.2:8000/` for emulator and editable in E6 Settings for LAN classroom demos).
- **`telemetry/`**:
  - `ClockOffsetSync`: calls `GET /time` taking `t0 = System.currentTimeMillis()`, `t1 = System.currentTimeMillis()`, computing `clockOffsetMs = serverWallTimeMs - (t0 + t1) / 2` (median of 3 samples, refreshed periodically) so device-to-host latency measurements are offset-compensated (`REQ-016`, `EVAL-004`).
  - `LatencyTelemetryLogger`: records correlated wall-clock events (`journeyId`, `scenarioId`, `executionId`, `sequenceNumber`, `transportMode`, `pollIntervalS`, `workerGeneratedAtMs`, `predictionCompletedAtMs`, `serverPublishedAtMs`, `clientRequestStartMs`, `clientReceivedAtMs`, `clientRenderedAtMs`, `clockOffsetMs`, `status`, `errorCode`) and batches `POST /telemetry/events` asynchronously without blocking UI.
- **`data/repository/`**:
  - `SyncConfig`: `mode: SyncMode` (`POLLING` | `LIVE_DEMO_STREAM`), `pollIntervalSeconds: Int` (default `5`; presets `1`, `5`, `30`).
  - `ActiveJourneyUiState`: `route`, `stops`, `selectedStopId`, `snapshot`, `predictionsByStop`, `dataSource` (`SIMULATION` | `RECORDED_REPLAY` | `DEMONSTRATION` | `CACHED`), `isOnline`, `isStale`, `lastReceivedAtMs`, `isLoading`, `errorMessage`, `demoPlaybackState` (`PLAYING` | `PAUSED` | `STOPPED`), `syncConfig`.
  - `TransitRepository`:
    - Exposes single shared `StateFlow<ActiveJourneyUiState>` consumed by E1, E2, E5 Stop-Anchored AR, and Tabletop 3D AR (`BR-010`).
    - Lifecycle-aware sync control: `startForegroundSync()` / `stopForegroundSync()` so polling and SSE run ONLY while a screen is visible and online (`REQ-011`).
    - Applies `SequenceOrderingGuard` (`T008`) to EVERY incoming REST or SSE snapshot before writing to Room or updating `StateFlow` (`BR-009`).
    - On network failure / HTTP error / timeout: keeps last valid cached Room data visible, sets `isOnline = false`, `isStale = true`, exposes `retrySync()` (`REQ-011`, `BR-004`).
    - `DemoTripPlayer`: loads `assets/demo_trip.json`, emits snapshots locally with `Play` / `Pause` / `Restart` advancing its own playback clock, clearly marked `DEMONSTRATION` (`REQ-011`, `BR-003`, `BR-004`).
    - Experiment methods (`saveScenario`, `deleteScenario`, `submitExperiment`, `pollExperimentStatus`): blocks new server submissions when offline or in demonstration mode with an explicit connectivity error (`BR-015`), prevents duplicate in-flight submissions per scenario (`BR-008`), and persists results in `ScenarioResultEntity`.
    - Favourites methods (`toggleFavourite`, `moveFavouriteUp`, `moveFavouriteDown`, `observeFavourites`) backed by Room (`REQ-010`).

## Implementation steps
1. Implement `kotlinx.serialization` DTOs matching [docs/ARCHITECTURE.md](../ARCHITECTURE.md) §4.2 and `MobilisApiService` + `SnapshotSseClient` in `data/remote/`.
2. Implement `ClockOffsetSync` and `LatencyTelemetryLogger` in `telemetry/` with safe failure isolation (telemetry upload errors never fail user requests).
3. Implement `DemoTripPlayer` reading `assets/demo_trip.json` and advancing snapshots on a coroutine ticker when `PLAYING` (freezing completely on `PAUSED`, resetting sequence on `RESTART`).
4. Implement `TransitRepository` coordinating Room DAOs (`T008`), `MobilisApiService`, `SnapshotSseClient`, `SequenceOrderingGuard`, `ArrivalCalculator`, `DemoTripPlayer`, and `LatencyTelemetryLogger`.
5. Write comprehensive JVM unit tests using `MockWebServer` (OkHttp) + Robolectric Room DB + `TestDispatcher` verifying polling lifecycle, SSE push updates, out-of-order rejection, execution-ID restart acceptance, offline cache retention + Retry, offline experiment blocking, duplicate-submit prevention, and bundled demo Play/Pause behavior.

## Edge cases and security
- Validate configured server URL scheme is strictly `http://` or `https://` in `ServerConfigStore`.
- Cancel polling and SSE coroutines immediately in `stopForegroundSync()` (triggered from Activity/Compose lifecycle `ON_STOP`) so background battery/network drain never happens (`REQ-011`).
- Ensure client `markRendered(journeyId, sequenceNumber)` hooks into `LatencyTelemetryLogger` cleanly so `client_rendered_at_ms` reflects actual Compose frame display (`EVAL-004`).
- Handle HTTP `422`/`404`/`500` `ErrorEnvelope` responses gracefully without overwriting valid cached snapshots.
