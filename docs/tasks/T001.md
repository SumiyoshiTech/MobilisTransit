## Objective
Bootstrap the Python 3.13 virtual environment (`.venv`) and dependency specification (`pyproject.toml`) inside `MobilisTransit/`, generate the canonical `sumo/manifest.json` + `sumo/manifest.schema.json` directly from the colleague's committed Mobilis Line 9 SUMO assets (`sumo/linha9.sumocfg`, `leiria.net.xml.gz`, `gtfs_pt_stops.add.xml`, `gtfs_pt_vehicles_L9.add.xml`, `DEC-004`), ship a fast runnable 4-stop synthetic SUMO fixture (`sumo/fixtures/sample_line9/`) for unit/CI tests, and implement safe SUMO binary discovery and manifest validation (`REQ-001`, `CON-002`, `CON-011`).

## Contracts
- **Workspace rules (CRITICAL)**:
  - **NEVER** create `sumo/__init__.py` or top-level `.py` files inside `sumo/` (prevents shadowing PyPI's `eclipse-sumo` package).
  - **DO NOT** overwrite or delete the canonical Line 9 files in `sumo/` (`linha9.sumocfg`, `leiria.net.xml.gz`, `pt_vtypes.xml`, `gtfs_pt_stops.add.xml`, `gtfs_pt_vehicles_L9.add.xml`), `sumo/deprecated/`, or `README.md`.
  - **Extend** the existing `.gitignore` (preserve all colleague rules and append MobilisTransit backend/ML/Android ignores).
- **`backend/app/simulation/sumo_env.py`**:
  - `resolve_sumo_binary(gui: bool = False) -> Path`: checks in order (1) `os.environ.get("SUMO_HOME")` (`bin/sumo.exe` or `bin/sumo`), (2) `shutil.which("sumo")`, (3) `importlib.metadata.distribution("eclipse-sumo")` locating `sumo/bin/sumo.exe` (or `sumo`) directly from site-packages without importing local `sumo/`. Raises `SumoNotFoundError` with actionable install instructions if missing.
  - `ensure_sumo_home_env() -> Path`: sets `SUMO_HOME` in the current process environment if resolved from `eclipse-sumo` (or validates existing system `SUMO_HOME`) so `traci` and `sumolib` work reliably on Windows.
- **`backend/app/simulation/manifest_loader.py`**:
  - Pydantic v2 models `StopManifest` and `NetworkManifest` matching [docs/ARCHITECTURE.md](../ARCHITECTURE.md) §4.1:
    - `net_file` supports both `.net.xml.gz` and `.net.xml`.
    - `route_file: str | None = None` (optional when routes/vehicles reside inside `additional_files`, as in `gtfs_pt_vehicles_L9.add.xml`).
    - `bus_vehicle_id: str` plus optional `bus_vehicle_prefix: str | None = None` (e.g., `"1010-"` for multi-trip Line 9).
    - Circular/loop route support: `stop_id` MUST be unique (`P01`..`P22`) and `sequence_index` strictly increasing (`0..N-1`), while `sumo_bus_stop_id` MAY repeat for start/end loop terminals (e.g., `gtfs_lra_0096` at `sequence_index` `0` and `21`).
  - `resolve_active_network_dir(preferred_dir: Path | None = None) -> Path`: uses `preferred_dir` if provided; else checks `sumo/` for a valid `.sumocfg` + `manifest.json`; falls back cleanly to `sumo/fixtures/sample_line9/` with a clear log warning indicating fixture mode.
  - `load_and_validate_manifest(network_dir: Path) -> NetworkManifest`: validates unique `stop_id`s, strictly increasing `sequence_index` (`0..N-1`), non-decreasing `distance_from_start_m`, `x_norm`/`y_norm` in `[0.0, 1.0]`, existence of referenced `.sumocfg`, `net_file`, optional `route_file`, and all `additional_files` strictly inside `network_dir`, and presence of every `sumo_bus_stop_id` inside the additional XML files.

- Ensure `sumo/` directory does NOT shadow `eclipse-sumo` even when running `pytest` from repository root (no `sumo/__init__.py`).
