## Objective
Build the FastAPI-served Administration Web Interface (`/admin`) allowing analysts to browse and filter stored simulation runs, configure and launch paired SUMO delay experiments (stop hold + background traffic multiplier) via structured web forms, monitor job progress, and inspect stop-by-stop observed arrival tables and propagation charts — calling the exact same central REST/JSON endpoints as the Android app and upcoming LangGraph assistant (`REQ-014`, `BR-005`–`BR-008`, `DEC-002`).

## Contracts
- **Routes**:
  - `GET /` → redirects (`307`) to `/admin`.
  - `GET /admin` → renders the single-page/tabbed Administration Dashboard (`templates/admin.html`) served directly by FastAPI (zero Node/npm build step).
  - Static assets mounted at `/static` (`static/admin.css`, `static/admin.js`).
- **UI Panels inside `/admin`**:
  1. **System & Provenance Header**: Displays active route, network version, active `model_version`, SUMO status, and explicit *"Simulation-Based Prototype — Not Live Mobilis Telemetry"* banner (`BR-004`, `BR-014`).
  2. **Stored Runs & Experiments Browser**: Filter form (`demand_profile`, `min_hold_s`, `max_hold_s`, `status`) fetching `GET /experiments`, displaying experiment IDs (`EXP-001`, `EXP-002`), invariants (demand, seed, departure), intervention summary, status badge, and quick `Inspect / Compare` action.
  3. **Paired Delay Experiment Form**: Structured HTML form with client-side + server-side validation:
     - `name`, `route_id` (loaded from `GET /routes`), `intervention_stop_id` (loaded from `GET /routes/{id}/stops`), `stop_hold_s` (`0–900` integer), `traffic_multiplier` (`0.5–2.5`, default `1.0`), `demand_profile`, `departure_time` (`HH:MM:SS`), `random_seed`.
     - Submits `POST /experiments`, disables button while in-flight to prevent double submission (`BR-008`), preserves form inputs on validation/server errors (`BR-008`), and polls `GET /experiments/{job_id}` until `COMPLETED` or `FAILED`.
  4. **Stop-by-Stop Observed Comparison Table & Propagation Chart**:
     - Displays `baseline_experiment_id` vs. `perturbed_experiment_id`, shared invariants summary (`BR-005`), explicit *"Observed Simulated Arrivals"* header (`BR-006`), stop-by-stop table (`Stop`, `Baseline Arrival`, `Scenario Arrival`, `Observed Difference (s / min)`), and an inline SVG or Canvas bar/line chart showing delay propagation across stops (works 100% offline without external CDN failures!).
  5. **Assistant Tab / Dock Placeholder**: Clean container (`#agent-chat-panel`) ready to be activated in `T014` without rewriting the admin layout.

## Implementation steps
1. Create `backend/app/web/router.py` mounting Jinja2 templates and static files cleanly using `Path(__file__).resolve().parent`.
2. Design clean, high-contrast, accessible HTML/CSS (`templates/admin.html`, `static/admin.css`) following the project's visual language (clean slate `#F8FAFC` background, navy `#1E3A8A` headings, blue `#0284C7` data highlights, amber `#D97706` delay/retention badges, non-color text indicators per `CON-009`).
3. Implement `static/admin.js` invoking ONLY the canonical backend REST API (`/health`, `/routes`, `/routes/{id}/stops`, `/experiments`, `/experiments/{id}`, `/experiments/compare`) with strict `textContent` / DOM construction (never `innerHTML` with untrusted API strings — prevents XSS), inline SVG chart rendering for stop-by-stop delay propagation (zero external CDN dependency), and job-status polling.
4. Register the web router and static mount in `backend/app/main.py`.
5. Write `backend/tests/test_admin_web.py` verifying `/`, `/admin`, static assets, presence of form controls (including both stop hold and traffic multiplier per `DEC-002`), and end-to-end API flow triggered via the exact payload shape the web form submits.

## Edge cases and security
- Escape all dynamic values in Jinja2 (autoescape enabled) and use `textContent` in `admin.js` to prevent XSS via experiment names or error messages.
- Render comparison charts natively via lightweight JS `<svg>`/`<canvas>` instead of relying on an internet CDN so indoor classroom demos without internet access work reliably (`CON-011`).
- Keep form field values intact when `POST /experiments` returns `422`/`500` and render the structured `ErrorEnvelope.message` clearly (`BR-008`).
