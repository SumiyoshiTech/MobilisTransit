## Objective
Build the Material 3 Jetpack Compose application shell (4-destination bottom bar + context-preserving back stack), shared accessible provenance header and offline stale banner, self-drawn 2D schematic Route Overview screen (`E1`, zero external map SDKs), and Stop Arrival Details screen (`E2`) (`REQ-007`, `REQ-008`, `REQ-011`, `BR-001`–`BR-004`, `CON-005`, `CON-009`).

## Contracts
- **Application Container (`MobilisApp.kt`)**: Lightweight manual dependency container (no heavy DI boilerplate needed) providing singleton `MobilisDatabase`, `TransitRepository`, and ViewModel factories.
- **Navigation Shell (`ui/navigation/MobilisNavGraph.kt`)**:
  - 4 primary bottom-bar destinations (`REQ-011`): `Route` (E1), `Favourites` (E6), `Scenarios` (E3), `AR` (E5) — wire clean placeholder composables for E3/E4, E6, and E5 that `T011` and `T012` will replace without changing route signatures!
  - Secondary screens: `stop_detail/{stopId}` (E2) and `experiment_compare/{jobId}` (E4) preserving back navigation context (`REQ-011`).
  - Lifecycle observer in `MainActivity` calls `repository.startForegroundSync()` on `ON_START` and `repository.stopForegroundSync()` on `ON_STOP`.
- **Shared Components (`ui/components/`)**:
  - `ProvenanceHeader`: displays Route name/selector, Data Source badge (`SIMULATION` | `RECORDED_REPLAY` | `DEMONSTRATION` | `CACHED`), Journey ID, Simulation Clock (`HH:MM:SS`) + Playback status (`Playing`/`Paused`), Reception Age (`Received X s ago`), and Online/Offline badge — every status uses explicit text + icon (never color alone, `CON-009`).
  - `OfflineStaleBanner`: shown across info screens whenever `!isOnline || isStale`, displaying `[!] OFFLINE`, last received timestamp, explanation (*"Cached predictions; not refreshed"*), and functional `Try again` button (`REQ-011`, `BR-004`).
  - `RouteDiagramCanvas`: custom Jetpack Compose `Canvas` (`CON-005`, NO Google Maps/Mapbox) drawing ordered Line 9 stops using normalized route progression / `x_norm`/`y_norm`, travel direction indicator, visited vs. next stop markers, active bus icon positioned proportionally along the current segment, and tap hit-testing to select any stop directly on the diagram (`REQ-007`) with `semantics` content descriptions (`CON-009`).
- **E1 (`ui/route/RouteScreen.kt`, `RouteViewModel.kt`)**:
  - Displays `ProvenanceHeader`, manual `Refresh` action, `OfflineStaleBanner` when applicable, `RouteDiagramCanvas`, Upcoming Arrivals list (stop code, name, predicted arrival or `Unavailable`, predicted delay ONLY if reference timetable exists per `BR-001`), tap stop → E2, and `Save favourite` toggle (`REQ-007`).
  - Handles Loading (`CircularProgressIndicator`), Empty (explanatory empty state), and Error states (`REQ-011`).
  - Invokes `repository.notifyFrameRendered(...)` via `SideEffect` / `LaunchedEffect(snapshot.sequenceNumber)` for `REQ-016` latency telemetry.
- **E2 (`ui/stopdetail/StopDetailScreen.kt`, `StopDetailViewModel.kt`)**:
  - Displays selected stop name & code, `ProvenanceHeader`, `OfflineStaleBanner`, and clearly separated Next Arrival fields (`REQ-008`):
    - **Predicted arrival** (or `Unavailable` when `!predictionAvailable`, `BR-002`)
    - **Time remaining** (strictly against `simulationClockS`, frozen when paused/stale, `BR-003`)
    - **Reference timetable** (shown ONLY when non-null; if null, omit both reference row and any delay label per `BR-001`)
    - **Predicted delay** (`prediction - reference`, shown ONLY when both exist per `BR-001`, styled with amber accent + explicit text `+3 min` / `On time` / `-1 min`)
    - **Vehicle ID & operational status**
  - Actions: `View on route` (back to E1 highlighting stop), `Open in AR` (navigates to E5 with selected stop), and `Add/Remove favourite` (`REQ-008`).

## Implementation steps
1. Implement Material 3 theme (`ui/theme/`) matching project palette (`#F8FAFC` light background, `#0F172A` ink, `#1E3A8A` primary navy, `#0284C7` accent blue, `#D97706` amber delay/warning) with dynamic `sp` font scaling (`CON-009`).
2. Implement `MobilisApp.kt`, `MainActivity.kt` (lifecycle-hooked sync), and `MobilisNavGraph.kt`.
3. Implement `ProvenanceHeader`, `OfflineStaleBanner`, and interactive `RouteDiagramCanvas` in `ui/components/`.
4. Implement `RouteViewModel` + `RouteScreen` (E1) and `StopDetailViewModel` + `StopDetailScreen` (E2) reading strictly from `TransitRepository.activeState`.
5. Write ViewModel unit tests (`RouteViewModelTest`, `StopDetailViewModelTest`) verifying E1 upcoming stop ordering, E2 missing reference timetable (`BR-001`), E2 missing prediction (`BR-002`), E2 paused clock freeze (`BR-003`), favourite toggle, and offline retry behavior.

## Edge cases and security
- Ensure large system font scaling (`fontScale = 1.5x–2.0x`) does not clip labels in `ProvenanceHeader` or E2 rows (`CON-009`) — use `FlowRow` / vertical stacking and scrollable columns.
- Ensure stops without coordinates fallback cleanly to an evenly spaced horizontal/vertical schematic layout in `RouteDiagramCanvas`.
- Ensure tapping a stop on E1 never crashes if predictions list is empty or incomplete.
