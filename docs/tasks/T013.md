# T013: Android Tabletop 3D Full-Route AR mode & unified AR/2D mode switching
- **State**: `todo`
- **Dependencies**: `T012`
- **Allowed files**: `android/app/src/main/java/pt/ulo/estg/mobilistransit/ui/ar/**`, `android/app/src/test/**`

## Objective
Implement the Tabletop 3D Full-Route Augmented Reality mode (`REQ-013`, `DEC-001`) using ARCore horizontal plane detection and SceneView/Filament so students and analysts can place the entire Mobilis Line 9 route onto an indoor desk surface, observe live vehicle movement and stop-to-stop delay propagation driven by the shared `TransitRepository`, and switch in a single tap between `Stop Marker AR` (E5), `Tabletop 3D Route`, and the `2D Screen` while preserving active journey/scenario state (`REQ-013`, `BR-010`, `BR-011`, `CON-004`, `CON-008`, `CON-009`).

> **Review Flag**: Complex / 3D AR plane-anchoring & scene-update task.

## Contracts
- **`ui/ar/TabletopRouteModel.kt`** (pure Kotlin geometry & state mapper, unit-testable on JVM!):
  - `TabletopStopNode3D`: `stopId`, `stopName`, `xMeters: Float`, `zMeters: Float` (mapped from `Stop.xNorm`/`yNorm` onto a configurable tabletop footprint, default `0.60 m × 0.35 m` centered on the anchor), `visited: Boolean`, `delaySeverity: DelaySeverity` (`ON_TIME`, `MODERATE_DELAY`, `HIGH_DELAY`, `NO_REFERENCE`, `UNAVAILABLE`), `badgeText: String` (e.g., `P03 +3m` — color + text coding per `CON-009`).
  - `TabletopBusPose3D`: `xMeters: Float`, `zMeters: Float`, `yawRadians: Float` interpolated strictly from `ActiveJourneyUiState.snapshot.vehicle` and ordered stops (`BR-010`).
  - `buildTabletopRouteSceneModel(state: ActiveJourneyUiState, footprintWidthM: Float = 0.60f, footprintDepthM: Float = 0.35f): TabletopRouteSceneModel`
- **`ui/ar/TabletopArContent.kt`**:
  - Configures ARCore `Config.PlaneFindingMode.HORIZONTAL` with `planeRenderer = true` until anchor placement (then optionally dims plane grid once placed).
  - User taps a detected horizontal plane (`onTouchEvent` / hit-test on `Plane`) → creates a single `AnchorNode` on the desk surface (with a `Reposition` button to clear & re-place cleanly).
  - Renders inside the `AnchorNode` using procedural Filament/SceneView nodes:
    1. Subtle translucent base mat representing the desk route footprint.
    2. Continuous 3D route track segments connecting all ordered Line 9 stops (highlighting delayed downstream segments with amber tint + text tags).
    3. Ordered 3D stop pillars for every Line 9 stop, tinted by `DelaySeverity` and paired with readable text labels (`stop_id` + delay or `No ref` / `N/A` per `BR-001`/`BR-002`/`CON-009`).
    4. Live 3D bus mesh moving smoothly along the full route as `ActiveJourneyUiState` updates (works for live SUMO, recorded replay, or offline demonstration!).
- **Unified Single-Tap Mode Switching (`ui/ar/ArScreen.kt`, `ArViewModel.kt`)**:
  - Top bar segmented control lets users switch in a single tap between `Stop Marker AR` (E5), `Tabletop 3D Route`, and `Open 2D` (`REQ-013`).
  - Switching modes tears down the previous AR anchor cleanly without dropping or resetting `TransitRepository.activeState` (selected route, journey, scenario, and stop stay preserved).
  - Retains identical lazy camera permission, unsupported-device fallback, and zero camera-frame storage guarantees (`BR-011`, `CON-008`).

## Implementation steps
1. Implement `TabletopRouteModel.kt` transforming normalized stop coordinates (`x_norm`, `y_norm`) and live vehicle progress into metric 3D coordinates, bus heading (`atan2`), and color+text delay annotations.
2. Extend `ArUiState` and `ArViewModel` with `TabletopPlacementState` (`SEARCHING_PLANE`, `PLANE_DETECTED`, `PLACED`, `TRACKING_LOST`), `placeTabletop()`, `resetTabletopPlacement()`, and `switchArMode(mode)` preserving shared journey state.
3. Implement `TabletopArContent.kt` using `ARScene` horizontal plane detection + Filament 3D track segments, stop pillars, delay labels, and live-updating 3D bus node.
4. Enable the `Tabletop 3D` mode tab in `ArScreen.kt` with single-tap switching to `Stop Marker AR` and `Open 2D`, plus `Reposition` and `Scale (0.5x / 1.0x / 1.5x)` controls for desk vs. classroom table sizes.
5. Write JVM unit tests (`TabletopRouteModelTest` and extended `ArViewModelTest`) verifying 3D coordinate projection bounds, bus interpolation & yaw across segments, color+text delay badges respecting `BR-001`/`BR-002`, and state-preserving mode switches (`Stop AR` ↔ `Tabletop 3D` ↔ `2D`).

## Edge cases and security
- Handle routes whose stops have colinear `y_norm` (e.g., straight-line schematic fixture) without division-by-zero when normalizing bounding box or computing bus yaw (`atan2`).
- Guard against tapping before any horizontal `Plane` is tracked (display helpful guidance: *"Move phone slowly over a flat desk surface, then tap to place Line 9"*).
- Ensure switching between `Stop Marker AR` and `Tabletop 3D` reconfigures ARCore session cleanly (`planeFindingMode` + `augmentedImageDatabase`) without leaking `AnchorNode`s.
