## Objective
Implement the core Stop-Anchored Augmented Reality screen (`E5`) using ARCore (`AR Optional`) `Augmented Images` and `io.github.sceneview:arsceneview` (Filament): detect printed stop reference images, anchor an arrival information card directly above a compact 3D mini-route showing neighbouring stops and the approaching 3D bus with color + text delay coding, read strictly from the shared `TransitRepository` (`BR-010`), enforce lazy camera permission & zero frame storage (`CON-008`), and provide robust 2D fallbacks (`REQ-012`, `BR-010`, `BR-011`, `CON-004`, `CON-008`, `CON-009`, `DEC-001`).

> **Review Flag**: Complex / ARCore hardware & privacy-sensitive task (marker confirmation gate, 3D scene node lifecycle, camera privacy compliance, graceful fallback on unsupported devices/emulators).

## Contracts
- **Printable Stop Reference Markers (`assets/ar_markers/`)**:
  - `markers_manifest.json` mapping `ar_marker_id` (e.g., `marker_p01`..`marker_p04`) → `stop_id`, `asset_filename`, `physical_width_m` (e.g., `0.18`).
  - High-contrast, feature-rich PNG reference marker images (`>= 600×600 px`, non-repeating geometric patterns + clear stop code header so ARCore `AugmentedImageDatabase` achieves high quality scores!).
- **AR State Machine (`ui/ar/ArUiState.kt`, `ArViewModel.kt`)**:
  - `ArAvailabilityState`: `CHECKING`, `SUPPORTED`, `UNSUPPORTED_DEVICE`, `INSTALL_REQUESTED`.
  - `CameraPermissionState`: `NOT_REQUESTED`, `GRANTED`, `DENIED`.
  - `ArViewMode`: `STOP_MARKER` (implemented in `T012`), `TABLETOP_ROUTE` (slot wired in `T013`).
  - `MarkerTrackingState`: `SCANNING`, `TRACKING_CONFIRMED(stopId, markerId)`, `TRACKING_LOST(lastStopId)`.
  - Consumes `TransitRepository.activeState` directly (`BR-010`) and derives `ArStopCardModel` (stop name, line code, predicted arrival or `Unavailable`, delay relative to reference timetable ONLY when reference exists per `BR-001`, source label, simulation clock, reception age) + `MiniRoute3DModel` (previous stop, current tracked stop, next stop, normalized approaching bus progress `0f..1f`, downstream delay status/text per stop).
- **Stop-Anchored AR Composable (`ui/ar/StopMarkerArContent.kt`)**:
  - **Lazy Availability & Permission (`CON-004`)**: Checks `ArCoreApk.getInstance().checkAvailability(context)` and requests `Manifest.permission.CAMERA` ONLY upon entering E5. Never crashes on emulators or non-ARCore phones — transitions cleanly to `ArFallbackPanel`.
  - **Strict Marker Confirmation Gate (`BR-011`)**: Configures ARCore `AugmentedImageDatabase` from `assets/ar_markers/` inside `ARScene(sessionConfiguration = ...)`. Anchors virtual nodes ONLY when an `AugmentedImage` transitions to `TrackingState.TRACKING` and `trackingMethod == FULL_TRACKING`.
  - **3D Scene Composition (SceneView / Filament)**:
    - Attached to `AugmentedImageNode`:
      1. **Upper Arrival Card** (using SceneView `ViewNode` or crisp textured bitmap plane / Compose-rendered anchored billboard card positioned directly above the marker) displaying Stop Name, Line 9, Predicted Arrival, Predicted Delay (if reference timetable exists), Data Source, Simulation Clock, and Reception Age.
      2. **Compact 3D Mini-Route** directly below the arrival card: procedural Filament 3D geometry (`CubeNode` / `CylinderNode` with `MaterialLoader` — zero fragile external `.glb` download required!) showing the track bar, 3 neighbouring stop pillars (`prev`, `current`, `next`) color-coded by delay severity + crisp text labels (`CON-009`), and an animated 3D bus mesh sliding smoothly along the track proportional to live bus progress from `ActiveJourneyUiState`.
  - **HUD Controls & Fallbacks (`BR-011`)**:
    - Top bar: Mode selector (`Stop AR` | `Tabletop 3D` [enabled in `T013`] | `Open 2D`) + `Exit`.
    - Status chip: `Scanning marker` / `Tracking active: <Stop>` / `Tracking lost — re-aim or use 2D`.
    - Bottom fallback actions: `Select stop` (manual stop picker) and `Open 2D view` (single-tap return to E2/E1 preserving active state).
- **Privacy Guarantee (`CON-008`)**:
  - ZERO calls to `frame.acquireCameraImage()` for persistence, ZERO writes to disk/MediaStore, ZERO network upload of camera data.

## Implementation steps

Implement `ArUiState.kt` and `ArViewModel.kt` (pure Kotlin, testable on JVM!) managing availability check results, permission state, marker confirmation & loss transitions, `ArStopCardModel` (enforcing `BR-001`, `BR-002`, `BR-010`), and `MiniRoute3DModel` computation from `TransitRepository.activeState`.
3. Implement `ArFallbackPanel.kt` handling `UNSUPPORTED_DEVICE`, `CAMERA_DENIED`, and `TRACKING_LOST` states with clear explanations, manual stop selection, and one-tap `Open 2D view`.
4. Implement `StopMarkerArContent.kt` and `ArScreen.kt` using `io.github.sceneview:arsceneview` (`ARScene`, `AugmentedImageNode`, procedural Filament 3D mini-route + anchored arrival card) and wire `ArScreen` into `MobilisNavGraph.kt`.
5. Write JVM unit tests (`ArViewModelTest`) verifying: panel is NEVER anchored before valid marker confirmation (`BR-011`); `ArStopCardModel` values match E2 values byte-for-byte from the same `ActiveJourneyUiState` (`BR-010`); missing reference timetable omits delay (`BR-001`); permission denial, unsupported device, and tracking loss expose explicit fallback states & 2D navigation (`BR-011`); and `MiniRoute3DModel` computes neighbouring stops and bus position accurately.

## Edge cases and security
- Guard `ARScene` initialization against `UnavailableException` / missing OpenGL ES 3.0 on emulators (`try/catch` routing cleanly to `UNSUPPORTED_DEVICE` fallback).
- Dispose Filament nodes cleanly when `AugmentedImage.trackingState == STOPPED` or composable leaves composition (`DisposableEffect`) to avoid GPU memory leaks.
- Verify no camera frames or image bytes are written anywhere in `ui/ar/` (`CON-008`).
