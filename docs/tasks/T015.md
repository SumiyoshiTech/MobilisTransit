## Objective
Implement the automated evaluation harnesses for synchronization latency & freshness (`EVAL-004`, `REQ-016`) and the 5-category × 5-repeat conversational agent audit (`EVAL-003`), plus the complete 2D vs. AR within-subjects usability study package (`EVAL-002`) with explicit simulation-domain validity disclaimers (`BR-014`, `DEL-005`).

## Contracts
- **`evaluation/latency_analysis.py` (`REQ-016`, `EVAL-004`, `DEC-003`)**:
  - CLI `python -m evaluation.latency_analysis --db <database_url> --output-json <path> --output-md <path>` (also accepts JSON export from `GET /telemetry/summary` or direct SQLite query).
  - Computes and reports separately for every `(transport_mode, poll_interval_s)` group (`1 s`, `5 s`, `30 s` polling + `LIVE_DEMO_STREAM` SSE):
    1. **Server-update-to-display latency** (`(client_rendered_at_ms + clock_offset_ms) - server_published_at_ms`): median, P95, and pass/fail against the provisional **`< 2000 ms` live demonstration target** (`DEC-003`, `main_changes7.tex` §5.3).
    2. **API request-to-display latency** (`client_rendered_at_ms - client_request_start_ms`): median, P95 (`apresentação.md` Part 3B).
    3. **Full end-to-end state freshness** (`(client_rendered_at_ms + clock_offset_ms) - worker_generated_at_ms`, including polling wait): median, P95.
    4. **Request failure rate** (`failed_events / total_events`) and **out-of-order rejection count**.
  - Explicitly notes clock-offset compensation and simulation-domain caveats (`BR-014`).
- **`evaluation/agent_eval.py` (`EVAL-003`, `BR-013`)**:
  - CLI `python -m evaluation.agent_eval --base-url http://127.0.0.1:8000 --repeats 5 --output-json <path> --output-md <path>` (plus `--offline-mock` mode for CI/unit testing!).
  - Executes the **5 mandatory prompt categories × `repeats` (default 5)** against `POST /agent/chat`:
    1. Query existing journey/scenario (`list_scenarios`)
    2. Run single delayed scenario (`run_delay_experiment` — including stop hold and traffic multiplier cases)
    3. Compare baseline vs. delayed run (`compare_experiments`)
    4. Handle ambiguous or out-of-range request (must set `needs_clarification=True` and invoke `0` tools)
    5. Report unavailable experiment ID (`EXP-9999` — must report unavailable without fabricated numbers)
  - Audits every response programmatically against live DB / REST ground truth for:
    - Exact expected tool selection
    - Valid arguments & zero unauthorized calls
    - `100%` numeric & experiment-ID fidelity between `structured_table` and DB records
    - Wall-clock completion time (s) & user step count, formatted side-by-side with a web-form comparison benchmark template (`EVAL-003`).
- **`evaluation/usability_protocol/` (`EVAL-002`, `BR-014`)**:
  - `STUDY_PROTOCOL.md`: Counterbalanced within-subjects protocol for **10–15 volunteer students** (Group A: 2D → AR; Group B: AR → 2D) on identical recorded Line 9 simulation runs, specifying the 4 core tasks (select target stop, read predicted arrival, save favourite / interpret scenario comparison, identify downstream stops affected by an injected delay), environment logging (device model, lighting lux/qualitative note, viewing distance), ethics/privacy notice (no camera frames or personal location saved per `CON-008`), and exploratory simulation-domain validity disclaimer (`BR-014`).
  - `recording_template.csv`: Ready-to-use CSV spreadsheet header (`participant_id,order_group,interface_mode,task_id,completed,accurate,completion_time_s,marker_tracking_failures,legibility_score_1_5,physical_effort_score_1_5,device_model,lighting_condition,viewing_distance_cm,notes`).
  - `PRINTABLE_MARKERS.md`: Instructions for printing the stop reference images from `android/app/src/main/assets/ar_markers/` at exact `18 cm × 18 cm` physical scale (`ar_marker_width_m = 0.18`) for indoor classroom testing.

## Implementation steps
1. Implement `evaluation/latency_analysis.py` reading `telemetry_events` from SQLAlchemy DB (or JSON fixture), computing all three decomposed latency metrics + failure rates, and rendering JSON + Markdown summary reports.
2. Implement `evaluation/agent_eval.py` with the 5-category × N-repeat test matrix, DB ground-truth verifier, and Markdown report generator (supporting both live FastAPI/Ollama server and in-process FastAPI `TestClient` mock mode).
3. Author `evaluation/usability_protocol/STUDY_PROTOCOL.md`, `recording_template.csv`, and `PRINTABLE_MARKERS.md`.
4. Write `evaluation/tests/test_evaluation_tools.py` verifying latency percentile math (exact median/P95/failure-rate checks on synthetic telemetry rows), 5×5 agent evaluation harness execution against in-process test backend, and presence/schema of the usability study CSV template.

## Edge cases and security
- Guard `latency_analysis.py` against empty telemetry tables or zero-success groups (report `null`/`N/A` cleanly without `ZeroDivisionError` or NumPy empty-array crashes).
- Ensure `agent_eval.py` never leaves dangling credentials in output reports and tags reports with the tested `llm_provider` and `llm_model`.
- Include explicit `BR-014` disclaimer header in every generated Markdown report stating that results reflect simulated SUMO conditions, not proven live operational accuracy.
